# Chatbot — Telegram-боты для агентства стримеров

В репозитории находятся два независимых Telegram-сервиса на Python:

1. **Бот заявок** — двуязычный сценарий первичного сбора заявок в GIRLS | Stream Agency.
2. **Agency Manager** — закрытый бот владельца агентства для подготовки вакансий и ручной или запланированной публикации в Telegram и VK.

Сервисы запускаются отдельно, используют разные Telegram-токены и базы данных. Это портфолио-проект и MVP: бот заявок не является официальной интеграцией Hilly, не подтверждает возраст или принадлежность фотографий и не обещает доход.

## Возможности и сценарии

### Бот заявок

Кандидат запускает бота, выбирает русский или английский язык, знакомится с условиями и может начать анкету. Перед сбором данных бот показывает согласие на передачу ответов и фотографий менеджеру. После согласия он задаёт вопросы об имени, возрасте, стране, опыте, доступном времени для эфиров, языках, Telegram username и желаемой дате начала.

Бот принимает только указанный пользователем возраст от 18 лет и просит прислать 2–3 обычные фотографии. После нажатия «Готово» анкета и фотографии пересылаются подключённому менеджеру. В меню также есть краткая информация о процессе и условиях, а также ссылка на менеджера.

Команды: `/start`, `/menu`, `/cancel`, `/delete_me`, `/claim`.

### Agency Manager

Бот доступен только Telegram-аккаунту с заданным `AGENCY_OWNER_ID`. Владелец может:

- создавать текст вакансии и просматривать последние вакансии;
- добавлять и просматривать целевые Telegram-каналы и VK-сообщества;
- публиковать выбранную вакансию сразу по явной команде;
- планировать публикацию на заданное время UTC, просматривать очередь и отменять ожидающую публикацию.

Команды: `/new`, `/vacancies`, `/addtg`, `/addvk`, `/targets`, `/post`, `/schedule`, `/queue`, `/cancel`.

Публиковать можно только в каналы и сообщества, где у владельца есть разрешение, а у бота или токена — необходимые права. Ошибки публикации показываются владельцу; автоматических повторных отправок нет.

## Запуск бота заявок

Требуются Python 3.10+ и отдельный Telegram-бот, созданный через @BotFather.

Из корня репозитория установите зависимости:

```bash
pip install -r requirements.txt
```

Создайте локальный `.env` по образцу [`.env.example`](.env.example) и укажите:

- `BOT_TOKEN` — токен бота заявок;
- `MANAGER_CLAIM_CODE` — длинный случайный секретный код (не менее 24 символов);
- `MANAGER_USERNAME` — username менеджера без `@` (по умолчанию `girls_mngr`);
- `DB_PATH` — путь к SQLite-базе привязки менеджера (по умолчанию `agency_bot.sqlite3`).

Запустите сервис из корня проекта:

```bash
python bot.py
```

Чтобы подключить получателя заявок, менеджер должен открыть бота заявок в личном чате и отправить `/claim ВАШ_СЕКРЕТНЫЙ_КОД`. Затем следует удалить сообщение с командой. Для подробного сценария проверки смотрите [BOT_SETUP.md](BOT_SETUP.md).

## Отдельный запуск Agency Manager

Создайте **другого** Telegram-бота через @BotFather, установите зависимости менеджерского сервиса и запускайте его отдельным процессом из корня репозитория:

```bash
pip install -r agency_manager/requirements.txt
python agency_manager/manager.py
```

Перед запуском задайте переменные окружения:

- `AGENCY_MANAGER_TOKEN` — отдельный токен менеджерского бота;
- `AGENCY_OWNER_ID` — числовой Telegram ID владельца;
- `AGENCY_MANAGER_DB` — путь к SQLite-базе (необязателен, по умолчанию `agency_manager.sqlite3`);
- `VK_GROUP_TOKEN` — токен сообщества VK с правом публикации (необязателен, нужен для VK).

Например, в bash переменные можно экспортировать перед запуском:

```bash
export AGENCY_MANAGER_TOKEN="..."
export AGENCY_OWNER_ID="123456789"
export AGENCY_MANAGER_DB="agency_manager.sqlite3"
export VK_GROUP_TOKEN="..."
python agency_manager/manager.py
```

При локальном запуске задайте эти переменные в окружении процесса. На хостинге добавьте их в настройки секретов соответствующего сервиса. **Не переиспользуйте токен бота заявок.** Смотрите [agency_manager/README.md](agency_manager/README.md) — там также описан запуск как отдельного Python-сервиса на HOKAS.

## Секреты и постоянное хранение

Не добавляйте `.env`, токены Telegram/VK и секретный код привязки менеджера в Git. Для локальных баз и `.env` настроены исключения в [`.gitignore`](.gitignore). На хостинге используйте переменные окружения или хранилище секретов платформы.

Обе базы SQLite нужно размещать на постоянном диске хостинга, если данные должны переживать перезапуск или повторное развёртывание:

- бот заявок сохраняет в своей базе только Telegram chat ID подключённого менеджера;
- Agency Manager сохраняет тексты вакансий, целевые площадки и очередь публикаций.

У бота заявок нет постоянного хранилища анкет: незавершённые ответы и фото находятся в памяти процесса и теряются при перезапуске. Передача заявки менеджеру выполняется через Telegram.

## Приватность и ограничения

- Сбор анкеты начинается после явного согласия пользователя; в форме запрашиваются обычные фотографии, интимные фото и документы не запрашиваются.
- Возраст указан самим кандидатом и автоматически не проверяется; принадлежность фотографий также не подтверждается.
- После пересылки ответы и фотографии доступны в чате Telegram менеджера. Команды `/cancel` и `/delete_me` очищают только текущие данные в памяти бота. Они **не удаляют** уже отправленные менеджеру сообщения — для этого нужно обратиться к менеджеру.
- Доступ к Agency Manager проверяется по Telegram ID владельца. Тексты вакансий, площадки и очередь хранятся в отдельной SQLite-базе.
- Работоспособность, сроки хранения данных и доступность постоянного диска зависят от настроек хостинга и Telegram. Для публичного запуска стоит отдельно определить срок хранения заявок и порядок удаления пересланных данных.
- Это не официальная интеграция Hilly. Условия платформы и доступность работы в конкретной стране нужно уточнять отдельно; гарантии дохода нет.

## Возможные улучшения

Это направления дальнейшей разработки, а не уже реализованные функции:

- добавить тесты диалогов, проверок ввода и планировщика публикаций;
- предусмотреть подтверждённый процесс удаления уже отправленной заявки и срок автоматической очистки данных;
- добавить журналирование статусов без записи содержимого заявок и понятную диагностику конфигурации;
- усилить защиту очереди от повторной публикации при сбоях и перезапуске;
- оформить раздельные инструкции для локальной разработки и нескольких вариантов хостинга.
